# VF 작업 카탈로그 — 저사양 모델 라우팅

> **사용법:** VF 관련 요청을 받으면 이 표에서 매칭되는 항목을 찾아 **명시된 명령만 실행**한다.
> 스스로 경로를 추론하거나 다른 방법을 시도하지 않는다.
> 표에 없으면: "카탈로그에 없는 작업입니다. 강한 모델로 전환하거나 사용자에게 확인 필요" 보고 후 대기.

## 🚨 공통 규칙

1. **탐색 금지** — 표에 있는 경로만 사용. LS 트럭오더/PDF 파싱/ORM 직접 탐사 등 우회 금지
2. **검증 필수** — 쓰기 작업(POST/등록/인쇄) 후에는 반드시 GET 재조회로 실측 보고
3. **인쇄/전송/삭제** = 부작용 작업. 카탈로그에 명시된 것만 실행, 테스트용 재실행 금지
4. **음성 인식 오류 대비** — 제품명이 안 맞으면 분류(category_lg)로 재검색

## 1. 제품 번호 → 제품명/재고 조회 ✅ 스크립트 있음

**트리거:** "N번 뭐야?" / "제품명/재고 알려줘" / "N번 재고 몇 개?"
```bash
python E:/coding/VF-new/backend/scripts/vf_product_lookup.py <번호>
python E:/coding/VF-new/backend/scripts/vf_product_lookup.py --name "야채"
```
번호 규칙: `320-A1-1-XXX`→XXX번, `320-A1-2-XXX`→2XXX번.
상세: `운영원칙/VF-제품번호-조회규칙-20260802.md`

## 2. 출차관리 — KPP 파렛트 전표 입력+출력 ✅ 스크립트 있음

**트리거:** "N호차에 M개 입력하고 파렛트/KPP 전표 출력해"
```bash
python E:/coding/VF-new/backend/scripts/vf_kpp_print.py <호차> <plt> [날짜]
```
전제: Chrome CDP 9222 + WPPS 로그인.
상세: `의사결정/VF-출차관리-권역별-수량-음성합산-입력-20260803.md` §5

## 3. 출차관리 — 권역 수량 입력 (음성 합산)

**트리거:** "1호차 이스트 둘, 미들 하나" / "2호차 G 셋"
약어: G=GMH, D=DGU, 미들/M=MIDDLE, 야마토=TW_YAMATO, EAST/WEST 풀네임, GZJ=GWJ
**실행:** Runbook §3의 6단계 (GET→합산→POST(?date= 필수)→GET 검증→보고)
상세: `의사결정/VF-출차관리-권역별-수량-음성합산-입력-20260803.md`

## 4. 출차관리 — LS 전표 인쇄 (봉인씰 합성)

**트리거:** "N호차 LS 인쇄" / "전표 찍어"
```bash
curl "http://localhost:5176/departure/api/print/{호차}?plt={N}&date={날짜}&seal_leftWing=...&seal_rightWing=...&seal_backDoor=..."
```
전제: 해당 호차 PDF 존재 (`ls_pdfs/{date}/{plate}.pdf`). 봉인씰 모르면 GET 조회 후 보고.
상세: `의사결정/VF-출차관리-권역별-수량-음성합산-입력-20260803.md` §4

## 5. 배차 요청 텍스트 생성/전송

**트리거:** "배차 요청" / "LS에 배차 요청해"
형식: `VF67 - {날짜} 배차 요청 드립니다` + `{HUB} {톤수} {시간} {호차}차` + 마무리 문구
스킬: `vf-dispatch-request`. 텍스트만 생성해서 보고(전송은 사용자 확인 후).

## 6. 출고 수량 조회 ⚠️ 스크립트 미완 (강한 모델 필요 또는 API 직접)

**트리거:** "N번 이번 주 출고수량" / "출고 내역 확인"
```bash
# 현재고+출고 통합: unified API
curl -s "http://127.0.0.1:5176/api/inventory/unified" | python -c "..."  # 필터링 필요
```
⚠️ 전용 스크립트 미완 — 스크립트화 우선순위 1번 (자주 쓰는 작업).

## 7. 재고 조사/발주 필요량

**트리거:** "재고 조사해" / "발주 얼마나 해야 해?"
- 현재고: `/api/master/specs`의 `current_stock` (제품별)
- 발주 필요량: `/api/inventory/unified` (스냅샷 기반, 없으면 0)
- ⚠️ 두 API 용도 혼동 금지 (MEMORY 정정 이력 2026-08-04)

## 8. 생산 계획 등록/수정 🔒 복잡한 작업 — 강한 모델 필요

스킬: `vf2-production-system`. 색상→금형→수량 순서 확인 필수. 임의 추정 금지.
