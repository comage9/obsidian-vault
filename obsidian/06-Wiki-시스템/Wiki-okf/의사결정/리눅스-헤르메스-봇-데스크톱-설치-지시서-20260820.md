## 3. OmniRoute 연결 설정

### 옵션 A: Windows OmniRoute에 원격 접속 (권장 — 간단)

```bash
# config.yaml model 섹션 수정
hermes config set model.default "auto/cheap"
hermes config set model.provider omniroute
hermes config set model.base_url "http://<WINDOWS_IP>:20128/v1"
```

> Windows의 OmniRoute `.env`에서 외부 접속 허용 필요:
> - `OMNIROUTE_HOST=0.0.0.0` 설정 후 OmniRoute 재시작
> - 방화벽 20128 포트 개방

### 옵션 B: 우분투에 OmniRoute 별도 설치

```bash
# Node.js 20+ 필요
node --version  # 20.x 이상 확인

# OmniRoute 설치
npm install -g omniroute

# API 키 설정 (~/.omniroute/.env)
# OmniRoute 관리자 페이지(http://localhost:20128)에서 설정
# 비번: CHANGEME

# 실행
omniroute dev  # 개발 모드 (포어그라운드)
# 또는
omniroute start # 백그라운드
```

```bash

**Role:** VF-new 보노하우스 출차·재고·생산 관리 전담 에이전트
**Handle:** @vf-op (profile `vf-op`)
**Model:** omniroute / auto/cheap (비용 효율 라우팅)

## 성격 · 운영 원칙

- **즉시 실행 우선.** 출차/재고/생산/인쇄/권역 지시는 **VF MCP 도구(`mcp__vf_*`)** 로 즉시 실행.
  브라우저 탐색·ORM 우회 경로 탐색 금지. 만든 도구를 쓴다.

- **사실만.** 헛소리·추측·과장 금지. 모르면 "모릅니다" 하고 검증.
- **검증 후 보고.** curl/stat/ps로 직접 확인한 결과만 보고. exit 0 ≠ 성공.
- **단순성 우선(D7).** 기존 스킬·API·웹 UI 버튼이 있으면 그것을 쓴다. 복잡한 재구현 금지.
- **비용 의식.** VF 정기 작업은 저비용 라우팅(auto/cheap). 복잡 판단만 상위 모델.

## 담당 영역

## 필수 절차

1. **Tool-First:** 작업 전 `skills_list()` + `session_search()` + `fact_store search` 병렬.
2. **VF 라우팅 카탈로그:** `Wiki/운영원칙/VF-작업-카탈로그-저사양모델-라우팅-20260804.md` 우선 참조.
```

## 8. Hermes 데스크톱 앱 설치 (Linux)

### 8-1. 빌드 의존성 설치

```bash
# Node.js 20+ (nvm으로 설치 권장)
curl -fsSL https://fnm.vercel.app/install | bash
fnm install 20
fnm use 20

# 빌드 도구
sudo apt install -y build-essential libgtk-3-dev libnotify-dev \
  libtst5-dev libxss1 libgconf-2-4 libnss3 libxss1 libasound2 \
  libxtst6 xauth xvfb

# Hermes 소스 코드 (이미 설치된 hermes-agent 디렉토리 사용)
cd ~/.hermes/hermes-agent
# 또는 git clone:
# git clone https://github.com/NousResearch/hermes-agent.git ~/.hermes/hermes-agent
```

### 8-2. 데스크톱 앱 빌드

```bash
cd ~/.hermes/hermes-agent

# 의존성 설치
npm install

# 데스크톱 앱 의존성
npm run install:desktop

# Linux 빌드 (AppImage + deb + rpm)
cd apps/desktop
npm run dist:linux
```

### 8-3. 빌드 결과물 설치

```bash
# 빌드 결과 위치: apps/desktop/dist/
ls dist/  # .AppImage, .deb 파일 확인

# 방법 1: AppImage (권장 — 설치 불필요)
chmod +x dist/hermes-*.AppImage
./dist/hermes-*.AppImage

# 방법 2: deb 패키지 설치
sudo dpkg -i dist/hermes-*.deb
# 실행: hermes-desktop  또는 앱 메뉴에서 Hermes 선택
```

> **⚠️ 빌드 시간:** 약 5~10분 소요. `NODE_OPTIONS=--max-old-space-size=16384` 환경변수가 이미 builder 스크립트에 포함되어 있음.
>
> **⚠️ X11/Wayland:** Wayland 환경에서 Electron 앱 이슈 시 `GDK_BACKEND=x11` 환경변수 추가.

> 우분투에서는 VF/KPP 백엔드 서버가 실행 중이어야 하고, 경로를 Linux에 맞게 수정해야 함.

```bash
  --command python3 \
  --args "/path/to/VF-new/backend/mcp_server.py"
```

### KPP MCP

```bash
hermes -p vf-op mcp add kpp \
  --command python3 \
  --args "/path/to/KPP/kpp-mcp-server/server.py"
```

```bash
hermes mcp add playwright \
  --command npx \
  --args "@anthropic/mcp-playwright"
```

> VF/KPP 백엔드가 우분투에 없다면 MCP 없이 텍스트 기반 응답만 가능. Windows에서 VF 작업 권장.

## 12. 함정 및 주의사항

| # | 함정 | 해결 |
|---|------|------|
| 1 | **Telegram 409 Conflict** — 동일 봇 토큰으로 두 기기 게이트웨이 동시 실행 시 | 우분투는 로컬 전용(게이트웨이 미실행) 또는 별도 토큰 |
| 2 | **OmniRoute 원격 접속** — localhost만 바인딩된 경우 | `OMNIROUTE_HOST=0.0.0.0` 설정 + 방화벽 20128 개방 |
| 3 | **Syncthing 데이터 소실** — sendreceive에서 folder marker 오류 시 | 반드시 sendonly로 최초 동기화, 검증 후 sendreceive |
| 4 | **MCP 서버 경로** — Windows 경로(`E:\coding\...`)가 Linux에서 무효 | Linux 경로로 수정, VF/KPP 백엔드 Linux 설치 필요 |
| 5 | **Electron Wayland** — Wayland에서 Electron 앱 깜빡임/크래시 | `GDK_BACKEND=x11` 환경변수 |
| 6 | **메모리 공유** — fact_store(Holographic)는 각 기기 독립 SQLite | fact_store 내용은 수동으로 동기화 불가. MEMORY.md/USER.md만 Syncthing 공유 |
| 7 | **rules.json** — 각 에이전트 고유 파일, Git/Syncthing 공유 안 됨 | 직접 복사하여 `~/.hermes/rules.json` 생성 + `hermes config set prefill_messages_file` |
