# VF 제품 번호 조회 — 저사양 모델 대책

## 배경 (2026-08-04)

deepseek-v4-flash 모델 세션에서 "제품 번호 2115번 제품명+재고" 질문 시 실패:
1. 위키 `VF-제품번호-조회규칙-20260802.md`를 확인하라는 지시를 이행하지 못함 (문서-질문 연결 실패)
2. Django ORM 직접 탐사 → 비어 있는 `inventory_items` 테이블만 보고 "재고 0개" 오보
3. 정답: `/api/master/specs`의 `current_stock` = 51개 (compute_current_stock 공식)

**원인:** 회수가 모델 재량 의존 + MEMORY에 잘못된 SoT 기재(unified "없으면 0")

## 대책 4종

### A. 조회 스크립트 (즉시 실행)
`E:/coding/VF-new/backend/scripts/vf_product_lookup.py`
- 사용법: `python scripts/vf_product_lookup.py 2115` (또는 --name "야채 4단 화이트", --barcode R0161...)
- 동작: 번호→로케이션 역산(A1-1-N→N, A1-2-N→2N) → `/api/master/specs` 조회 → 제품명+현재고+바코드+로케이션 출력
- 저사양 모델은 스크립트 실행만 하면 됨 (Runbook 전략)

### B. rules.json 키워드 라우팅 (즉시 실행)
rules.json에 1개 항목 추가:
"제품 번호/N번/제품명/재고/location/320-A1" 키워드 수신 시
→ Wiki `운영원칙/VF-제품번호-조회규칙-20260802.md` 읽기 강제
→ `vf_product_lookup.py` 실행 강제, Django ORM 직접 탐사 금지

### C. MEMORY 정정 (즉시 실행)
- 기존(오류): "현재고 SoT=GET /api/inventory/unified (없으면 0)"
- 정정: 제품 조회 현재고 SoT = `/api/master/specs`의 `current_stock`
  (inventory_stock.py compute_current_stock = 스냅샷+입고−출고+조정)
- unified는 재고 장부 페이지용(스냅샷 universe 기반). 발주 필요량 계산 시에만 사용.
  "없으면 0"은 스냅샷에 없는 품목(=출고 실적 없거나 미업로드)에 한정.

### D. master_specs 제품 번호 컬럼 명시 (Claude Code 위임)
- master_specs 모델에 `product_number` (int, derived) 컬럼 추가 + 마이그레이션
- 파생 규칙: location `320-A1-1-XXX` → XXX, `320-A1-2-XXX` → 2XXX
- master/specs API 응답 + 제품 마스터 페이지에 "제품 번호" 컬럼 노출
- sync 시 자동 재계산 (location 변경 시 갱신)
- 위임 대상: Claude Code (`claude -p`, VF-new 원본 E:\coding\VF-new)
