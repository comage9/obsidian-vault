# 제품번호 파생 규칙 교정 (2-XX → 20XX) + 마스터 84건 동기화 (2026-08-19)

## 배경
사용자: "모던 플러스 28번은 어디 갔어?" — 검색에서 "28"이 탑백 리빙박스로 나옴.

## 근본 원인 (3중 확인)
1. **백엔드 `_product_number_from_location` 규칙 버그**: `int("2"+suffix)`로 계산 → 320-A1-2-8 → **28** (2008이어야 함), 2-34 → 234 (2034여야)
2. **프론트 `locToPnum` 동일 버그**: `"2"+m2[1]` → 2-8 → "28"
3. **마스터 DB 84건 오기재**: 2-XX(두 자리 이하) 전부 2XX로 저장 → 28번이 모던플러스(1-28)와 탑백(2-8)에 중복 → masterMap 덮어쓰기로 모던플러스 28이 미배치/검색에서 누락

올바른 규칙 (사용자 확정 2026-08-06, a-data.ts가 이미 사용):
- 320-A1-1-XXX → XXX
- 320-A1-2-XX(2자리 이하) → 20XX (2-8→2008, 2-34→2034, 2-85→2085)
- 320-A1-2-XXX(3자리) → 2XXX (2-115→2115)

## 검증
- 백엔드 단위 테스트 8/8 PASS (1-28→28, 2-8→2008, 2-34→2034, 2-85→2085, 2-115→2115, 2-145→2145)
- tsc 수정 파일 0 에러
- **브라우저 실측**: "28" 검색 → **1위: 모던플러스 서랍장 2단 화이트 + 미배치 · 320-A1-1-28 표시** ✅
- pnum=28 중복 해소 (모던플러스 단독), pnum=2008 = 탑백 52L 화이트

## 결론 (사용자 질문 답)
- **모던 플러스 28번 (모던플러스 서랍장 2단 화이트) = 현재 미배치 상태**
- 검색에 안 보였던 이유: 탑백 리빙박스(2-8)가 28번으로 오기재되어 28이 겹침 → "이미 배치됨"으로 오판
- 이제 "28" 검색 → 모던플러스 28 1위 + 미배치 안내, "2008" 검색 → 탑백(배치됨 A-L6-14)
